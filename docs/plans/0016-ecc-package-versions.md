# ECC: снимки пакетов и откат, этап 2b

Статус: этап 2b проверен Windows/Linux CI и native Windows CPU.
База 311693a, продолжение PR #4; проверенный код e158480.

Результат: выбранные навыки из JSON/SKILL.md/каталога устанавливаются в один
локальный *.lyra-skills.json. Снимок содержит id пакета, указанную пользователем
версию/источник и SHA256 нормализованного JSON SkillPack. Текущая и одна предыдущая
версия хранятся вместе; откат атомарно меняет их местами. Источник после установки
можно переместить: runtime использует снимок, а не повторный импорт.

CLI skill-package install/show/rollback и Desktop «Помощники» используют один
модуль. Установка явно выбранных навыков не активирует scripts/hooks/resources
и не обращается в сеть. Metadata origin/version — заявление пользователя,
не проверенная подпись upstream. SHA256 обнаруживает повреждение, не доказывает
доверие автору. Переопределять сохранённую текущую/предыдущую версию нельзя;
глобальной истории всех когда-либо установленных версий нет.

Запись через временный файл в той же папке; cooperative create_new lock защищает
от двух одновременных операций Lyra. Старый файл при ошибке остаётся прежним.
Сломанные store/hash/schema, превышение лимитов и неизвестные id отклоняются.
Это не OS sandbox и не защита от другого процесса с доступом на запись.

Критерии:

- [x] Установка выбранного поднабора, неизменность снимка после изменения source.
- [x] Metadata/hash, конфликт версии, обновление и двусторонний откат.
- [x] Испорченный store и занятый lock не теряют рабочую версию.
- [x] CLI/runtime/Desktop используют один снимок; прежние источники совместимы.
- [x] fmt/Clippy/tests Windows/Linux, native Windows CLI/Desktop acceptance.

## Фактическая проверка, 2026-11-02

[Windows/Linux CI e158480](https://github.com/DraimCiDo/Lyra/actions/runs/41441359636)
завершился success: fmt/Clippy, default и HTTP/Desktop tests, tiny GGUF CPU
inference, release builds, starter acceptance и открытие окон. SHA256 двух
скачанных EXE программно сверены с CI SHA256SUMS.txt.

На ПК Windows проверен этот CPU-артефакт. CLI: выбран один реальный навык ECC
из двух; повтор той же версии не переписывает файл; изменение source не меняет
снимок; конфликт версии сохраняет прежние байты; обновление сохраняет previous;
откат работает в обе стороны. Занятый lock отклоняет операцию без изменения store.
Unicode/пробелы в имени store проверены. Повреждённый SHA256 блокирует chat до
HTTP-запроса и откат без перезаписи повреждённого файла. Loopback HTTP получает
дословную guidance установленного выбранного навыка, без невыбранного. Exit 0;
внешние API не вызывались. Это проверка транспорта, не качества ответа модели.

Native Desktop в отдельном APPDATA-профиле: выбрать навык → ввести metadata →
установить 1 → установить 2 → откатить на 1 → закрыть и перезапустить → загрузить
снимок. UI и CLI согласны: current 1 / previous 2, источник и SHA256 сохранены,
выбор и путь снимка восстановлены. Тестовое окно закрыто; профиль пользователя
не заменялся. Переустановка версии 2 в UI использовала тот же контент с новой
меткой; обновление содержимого отдельно проверено CLI-фикстурой.

[CUDA build e158480](https://github.com/DraimCiDo/Lyra/actions/runs/41441359659)
ещё выполняется; native CUDA этой ревизии не проверена. GPU-код/зависимости
не менялись. Локально Cargo/MSVC нет: Rust-сборка/тесты выполнены CI,
native acceptance — скачанным EXE на ПК.
