# Chat: достоверность, ошибки и ход работы

Продолжение UI-приёмки: пользователь обнаружил выдуманные сведения о Horizon /
Discord, повторение ответов при смене темы, выдуманную версию приложения,
вывод stderr llama.cpp вместо ошибки и отсутствие подробного хода работы.

Подтверждено исходниками: Desktop Chat не добавляет системный контракт и не
имеет инструментов web/repo; unconstrained GGUF использует greedy sampler;
ProjectPlan при ошибке копирует хвост stderr в сообщение. В сохранённом
неудачном ответе — «Истёк таймаут генерации». Нужна отдельная диагностика
качества модели; ограничения инструментов нельзя исправить обещанием поиска.

Работы:
1. Общий системный контракт Chat для GGUF/HTTP: реальные версия/модель,
   границы доступа, неоднозначные имена, отсутствие поиска, недоверие к прошлым ответам.
2. Версия/модель и явный запрос web-поиска обрабатываются контроллером;
   без подключённого поиска не выдаётся выдуманный результат. История сохраняет роли.
3. Sampling только local-chat: repetition penalty и обычный sampling;
   grammar/tool workflows сохраняют прежнюю детерминированность.
4. Таймаут отличается от отмены. Краткая ошибка в чате, полная диагностика в журнале.
5. Ограниченный список реальных progress/tool events во время и после операции;
   стадии модели, токены, время, исход каждого действия. Без имитации рассуждений.
6. Unit/HTTP regressions, Windows/Linux CI и native проверки смешанных вопросов,
   таймаута и хода генерации; предыдущая приёмка истории/GGUF остаётся валидной.

Статус: исправление.

Проба system contract на 1.5B: первая неизвестная тема и переход к 2+2 стали
корректнее, но follow-up после ложного assistant-факта сохранил выдумку. Поэтому
одного prompt недостаточно: добавлен controller guard для проектных/серверных
вопросов без явного пользовательского контекста и их именных follow-ups.
Guard не считает прежние assistant-ответы источником и не запускает модель.
