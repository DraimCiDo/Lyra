# M2 — локальный inference

Статус: CPU-интеграция завершена и проверена на Linux/Windows CI; CUDA не проверена. Исходная ветка `feat/local-cli`; работа — `feat/local-inference`.

Подключить встроенный llama.cpp через безопасную Rust-обёртку, без HTTP,
отдельного сервера, API-ключа и автоматического скачивания весов.
Добавить `generate` с явным GGUF, prompt, контекстом, числом потоков,
GPU layers, лимитом ответа и времени. CPU — исходная сборка; CUDA — явный
feature, не скрытый fallback. Отмена по Ctrl+C и проверки до загрузки весов.
Не включать shell/tool calls и изменение файлов проекта.

- [x] Сверить API закреплённого binding и его лицензию.
- [x] Реализовать загрузку GGUF, шаблон чата, потоковый ответ, лимиты и отмену.
- [x] Проверить ошибки аргументов/файлов и бюджет контекста без больших весов.
- [x] Выполнить реальную CPU-генерацию на небольшой тестовой модели, если доступна.
- [x] Обновить CI Windows/Linux и проверить нативную сборку.
- [x] Документировать ограничения, команды и реальные результаты; commit/push.

Модель пользователя и RTX/CUDA недоступны. Маленькая тестовая модель проверяет
только механизм генерации, не качество кодинга и не производительность 7B.
Числа RAM/VRAM не являются жёсткой sandbox-квотой: явный контекст ограничивает
KV-cache, но выделения native runtime могут закончиться OOM. Не обещать гарантированное
восстановление после OOM ОС. Таймаут проверяется между native операциями.

## Фактические проверки

- `cargo check --locked`: Linux, exit 0. Bindgen потребовал CMake/libclang и
  явный include-каталог GCC в данном минимальном cloud-образе. Toolchain
  установлен только в `/workspace/.lyra-tools`, системный PATH не менялся.
- `cargo test --locked`: exit 0, 5 модульных + 6 CLI + 3 inference теста;
  один реальный model smoke пропущен в обычном прогоне по назначению.
- Отдельно `LYRA_TEST_MODEL=... cargo test --locked --test inference -- --ignored`:
  exit 0, реальная CPU-загрузка и генерация текста с лимитом 4 токена.
- Smoke-модель: `ggml-org/models`, revision
  `499bc8821c6b12b4e53c5bffcb21ec206f212d81`, `tinyllamas/stories260K.gguf`,
  SHA-256 `270cba1bd5109f42d03350f60406024560464db173c0e387d91f0426d3bd256d`.
  Около 1,2 MB; не включена в Git и поставку. Проверяет механизм, не качество кодинга.
- `cargo clippy --locked --all-targets -- -D warnings`: exit 0.
- Сбор runtime-уведомлений для Windows: exit 0. Лицензии binding отсутствовали
  в registry-архиве, получены из точной upstream-ревизии из `.cargo_vcs_info.json`;
  vendored llama.cpp notices включены отдельно. Build-only зависимости не входят
  в runtime-уведомления.
- Проверено 50 локальных Markdown-ссылок и `git diff --check`.
- CI: https://github.com/DraimCiDo/Lyra/actions/runs/41018408419 — ожидается.

Границы проверки: Windows 11/CUDA, реальные OOM и качество 7B на ПК пользователя
не проверены. Отмена/таймер проверены на уровне контрольных точек; нельзя
выдавать это за мгновенное прерывание native вызова. Шаблоны всех GGUF не проверялись.

Дополнительно проверен готовый Linux release binary:

- `cargo build --release --locked`: успешно, 7 235 968 байт.
- Реальная генерация из пути с пробелами/кириллицей: exit 0, непустой stdout.
- Реальная токенизация слишком длинного prompt при context 128: exit 1,
  stdout пустой, ошибка переполнения (prompt не обрезается).
- SIGINT собственному процессу после начала native загрузки: exit 130.
- Кооперативный таймаут: собственный процесс приостановлен SIGSTOP на 1,15 с
  и возобновлён SIGCONT с `--timeout-secs 1`; exit 124. Это проверка wall-clock
  и контрольной точки, не обещание принудительной остановки C++ посередине вызова.

Первый CI `41018408419`: Linux success; Windows собрал EXE и выполнил
реальную CPU-генерацию, но упаковка упала на Python CP1252 при чтении Cargo
metadata. Исправлено явным `encoding="utf-8"` в subprocess, повторная упаковка
локально прошла. Новый CI проверяет исправление на Windows.

Проверка offline: release-бинарник запущен через `unshare -Urn` в отдельном
user/network namespace, без сети, с локальным GGUF. Генерация 4 токенов
прошла, exit 0, 14 байт stdout. Модель и runtime не обращались к внешнему сервису.
Linux binary использует системные libstdc++/libgcc/libm/libc, без внешней llama DLL.
Повторный CI после исправления упаковки: https://github.com/DraimCiDo/Lyra/actions/runs/41019643816.
