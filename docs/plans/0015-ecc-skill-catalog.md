## Результат и границы

CLI и Desktop принимают JSON, отдельный SKILL.md или явно выбранную папку
с SKILL.md в корне / непосредственных подпапках. Каталог сортируется по id;
дубликаты и некорректные элементы отклоняют весь каталог. Ресурсы, scripts и
hooks не исполняются. Нет автоматического обнаружения, скачивания upstream
или передачи каталога провайдеру: передаются только явно выбранные инструкции.

Desktop: раздел «Помощники», кнопка загрузки каталога, описания, просмотр
инструкций, несколько выбранных навыков в порядке выбора и очистка выбора.
HTTP feature не требуется. Старая настройка active_skill сохраняет смысл;
после изменения выбора используется active_skills. На запуске источник заново
валидируется, исчезнувший навык и превышение бюджета останавливают запуск.
Просмотр каталога не перечитывает диск на каждом кадре; обновление явное.

Границы: максимум 512 элементов корня / 256 навыков / 4 MiB содержимого,
64 KiB на файл / 16 KiB инструкции одного навыка; действующий общий бюджет
selected skills сохраняется. Нет рекурсивного чтения resources. Полный upstream
может превышать эти ограничения: нужен отобранный локальный каталог.
Канонические пути проверяются против корня; ссылки на внешние SKILL.md
отклоняются. Это проверка путей, не OS sandbox и не защита от конкурентной
подмены файлов другим процессом.

Точки входа: src/skills.rs load_source, src/lib.rs, src/agent.rs,
src/desktop/skills.rs, preferences и composer. Контракты backend/tools и
политика proposal/apply не меняются. Project planner пока не потребляет skills.

## Фактические проверки, 2026-11-02

[Windows/Linux CI b790209](https://github.com/DraimCiDo/Lyra/actions/runs/41436148353)
прошёл: fmt, Clippy, default и HTTP/Desktop tests, tiny GGUF CPU inference,
release builds, starter acceptance и открытие обоих Desktop окон.
Native Windows проверен именно CPU-артефакт этого run; SHA256 обоих EXE совпал
с SHA256SUMS.txt из CI. В отдельном APPDATA-профиле проверены два настоящих
SKILL.md установленного ECC: загрузка списка, preview, выбор в обратном порядке
каталога, composer, сохранение и полный перезапуск, предупреждение об исчезнувшем
файле и явная очистка. Исходный профиль/история пользователя не заменялись.

CLI → loopback HTTP fixture: 2 тела instructions переданы дословно и в порядке
выбора; guidance 26390 байт, exit 0. Дубликат и неизвестный id отклонены до
HTTP-запроса (0 дополнительных вызовов). Это проверка транспорта guidance,
не доказательство качества модели или экономии трафика. Внешний API не вызывался.
На Windows junction к внешней папке проигнорирован: CLI exit 0, в каталоге
только локальный навык. Unix symlink boundary проверяется unit-тестом CI.

[CUDA build b790209](https://github.com/DraimCiDo/Lyra/actions/runs/41436148202)
ещё компилируется; native CUDA-проверка этого инкремента не заявляется.
GPU-код и зависимости не менялись. Локально Cargo/MSVC нет; сборку и Rust-тесты
выполнял CI, затем EXE запускался на ПК.
