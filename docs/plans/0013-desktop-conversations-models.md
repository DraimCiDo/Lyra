# Desktop: чаты, рабочий контекст и установка GGUF

Запрос пользователя: расширенное окно, сохраняемая история, выбор Чат/Работа
для нового чата, агенты и репозиторий в composer, центрирование приветствия,
HTTP только в настройках, рекомендации и установка GGUF.

План:
1. Локальное ограниченное хранилище переписок: режим, repo, выбранные файлы,
   черновик и сообщения. Переключение заблокировано во время задачи. Отчёты и
   apply не восстанавливаются из истории; старые предложения не становятся правами.
2. Боковая история, composer с режимом/агентами/repo, окно 1160×760,
   приветствие в центре доступной области переписки при любом размере.
3. Закреплённый каталог официальных GGUF Qwen: подбор по RAM, явная установка,
   прогресс/отмена, SHA256/размер/GGUF header, атомарная запись без перезаписи.
   Существующая выбранная модель автоматически не заменяется.
4. Регрессии хранения/изоляции/режимов/загрузки, fmt/Clippy/CI и native Desktop.

Переопределяет прежние ограничения compact-only и memory-only из AGENTS.md
по явному запросу пользователя. История содержит сообщения и хранится локально;
HTTP не включается созданием чата или установкой модели. Новых зависимостей нет.

Статус: реализовано. Код Desktop — 39e3fa9; исправления Windows test fixtures —
28fa6d2 и d5010eb. Windows/Linux CI d5010eb прошёл (run 41342807583):
fmt, Clippy, Desktop/HTTP tests, release build и native CI smoke.

Приёмка Windows EXE d5010eb на ПК:
- Два отдельных чата: Чат без repo и Работа с repo; после перезапуска
  восстановились сообщения, режим, repo и неотправленный черновик.
- После переключения полный отчёт/панель apply не восстанавливается из истории.
- Рабочая read-only HTTP-фикстура завершена за 4 вызова; счётчик в ответе виден.
- Приветствие центрируется в области переписки при обычном и развёрнутом окне.
- Каталог предложил 7B по RAM; из UI установлена выбранная 1.5B. Размер и SHA256
  независимо сверены, модель автоматически выбрана, временных файлов не осталось.
- Скачанная GGUF ответила `OK` через local-chat, exit 0.

HTTP использовал только локальную заглушку; реальная генерация — локальную GGUF.
CUDA и подробные native результаты фиксируются отдельно в PR #3.
GUI-отмена загрузки отдельно не подтверждена: загрузка успела завершиться;
cancel signal и отказ на повреждении/перезаписи покрыты автоматическими тестами.
