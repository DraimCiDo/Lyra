# M0 — основа репозитория

Статус: локальная основа готова; создание GitHub-репозитория и push заблокированы правами интеграции.

## Задача и границы

Создать отдельный GitHub-репозиторий для AI-агента, основной сценарий которого —
кодинг на Windows. Подготовить README и AGENTS.md по принципам ReplayLite и
DraimCiDoMOD, выбрать язык и определить понятное продолжение разработки.
Runtime, Cargo-проект, API-вызовы и выпуск приложения не входят в задачу.

Исходное состояние: `/workspace` без исходников нового проекта и его истории.
Подключённый GitHub-профиль — DraimCiDo. Рабочее название — Lyra;
видимость — public по явному указанию пользователя.
Название Lyra выбрано по созвездию Лиры, без префикса Draim.

## Проверки и результат

Среда: Linux в облачном окружении. Документы не требуют Windows/Rust toolchain.
Нативная сборка, тесты приложения и реальные запросы к модели не выполняются:
приложение ещё не создано.

- Проверка 13 файлов и 32 локальных Markdown-ссылок: код выхода 0,
  все ссылки существуют, блоки кода сбалансированы, прежнее имя удалено.
- Проверка UTF-8/LF и скан типовых шаблонов приватных ключей/API-токенов:
  код выхода 0, совпадений нет. Это не полный аудит защищённости.
- `git check-ignore --no-index` подтверждает исключение `.env`, локальных сессий,
  логов и сборок. `Cargo.lock`, `.env.example`, README и AGENTS не игнорируются.

- `git diff --cached --check`: код выхода 0; проверен состав 13 файлов,
  только документация и настройки Git/редактора, runtime отсутствует.
- Создание публичного `DraimCiDo/Lyra` через `gh repo create`: отказ GraphQL
  `Resource not accessible by integration (createRepository)`.
- Повтор через официальный REST `POST /user/repos`: HTTP 403,
  `Resource not accessible by integration`. Репозиторий не создан, push не выполнен.
- Повторная проверка облачного окружения: сеть доступна, дополнительных
  настроенных GitHub-учётных данных нет. Запрашивать токены в переписке не требуется.

Для завершения M0 нужен пустой публичный репозиторий `DraimCiDo/Lyra`, созданный
владельцем, и доступ GitHub-интеграции на запись в него. После этого добавить
`origin`, выполнить `git push -u origin main`, сверить remote SHA/видимость и
обновить этот план. Не создавать в удалённом репозитории отдельный README,
чтобы не потребовалось объединять две начальные истории.
