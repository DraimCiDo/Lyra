# Lyra v2 preview

Lyra v2 is an offline-first coding agent. The Windows x64 preview includes a Desktop app and CLI. Extract both executables from the same ZIP. Bring a compatible GGUF model and the Microsoft VC++ v14 x64 runtime. A Linux Docker daemon with resource limits and a locally available digest-pinned image is required for automated task checks. Local chat and proposal review work without Docker.

In `lyra-v2-desktop.exe`, select a GGUF and project, optionally select a check configuration, then describe a coding task. Review the diff and check output before applying. Task checkpoints use a separate `lyra-v2/tasks` directory under the OS data location. Use **Open saved task** to reopen a checkpoint after restarting. A project publication interrupted during a write retains the shared Lyra recovery journal. Use `lyra-v2 recover --repo <project>` to inspect it.

From PowerShell, choose a new path for each task checkpoint, outside the project.

```powershell
.\lyra-v2.exe task --repo C:\src\example --state C:\work\lyra-task-01 --model C:\models\coder.gguf --task "Fix the addition function" --check-config C:\work\check.json
.\lyra-v2.exe show --state C:\work\lyra-task-01
.\lyra-v2.exe apply --state C:\work\lyra-task-01
```

Use `resume` with the same state and a local model after cancellation or interruption. Without a checker, the report shows verification as skipped. With a checker, Apply requires passing evidence for the candidate, and files that change after verification can block publication. A model cannot choose a checker or run shell commands.

The preview is distributed as a separate CI artifact. The v1 release, updater and task files use their existing locations.

## Import v1 data

Choose **Import v1 data**, select the folder with v1's `settings.json` and `conversations.json`, and review the preview before saving a v2 import file. You can reopen that file in v2, load an imported conversation, or use its model and project paths. The CLI can preview with `import-v1 --source <folder>` and save with `--into <file>`. Import keeps the original files intact. Each snapshot includes the supported data once. Cloud consent, checker settings, credentials, v1 task reports and journals stay with v1.

## Optional integrations

- Use `--reviewer` on a task to ask a read-only model reviewer to inspect the proposals. The configured checker still provides verification.
- `task-http` requires a provider registry, explicit provider and model identifiers, and `--allow-context-upload`. The selected provider receives task and workspace context. Provider configuration and credentials are supplied separately.
- Use `github-issue --repo <owner/name> --number <issue> --out <task.txt>`, then run a task with `--task-file <task.txt>`. After reviewing a proposal with a passing check, use `github-publish` with its state and the target branch and PR metadata to open a draft.
- Use `graph import` for Graphify exports, or `graph graphify` with an installed external Graphify executable for offline code extraction.
