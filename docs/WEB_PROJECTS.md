# Веб-проекты: стек и визуальное качество

Для нового сайта Lyra предлагает профиль **Vue / TypeScript**. В существующем
репозитории сначала учитывает package.json, lockfile и фактический стек:
React-проект не становится Vue-проектом только из-за нового предпочтения.
Профиль есть в документации/CLI (`vue-typescript`) и доступен AI-планировщику;
в чате выбор отдельной формы не требуется.

## Что сообщить в чате

Назначение сайта, аудитория, основные страницы/действия, реальный текст и визуальные
референсы помогают больше, чем просьба «сделать красиво». Укажи нужный стек,
ограничения и примеры понравившихся решений. Если важны SSR, индексация, авторизация,
хранение данных или интеграции, опиши их: Vite SPA подходит не для каждой задачи.
Неизвестное можно уточнить следующими сообщениями.

Рекомендации модели включают типографику, интервалы, палитру и состояния компонентов;
адаптивность, клавиатуру/фокус, подписи полей, контраст; loading/empty/error состояния
и умеренные анимации с учётом prefers-reduced-motion. Проверять нужно реальный
контент и взаимодействия на мобильном и настольном экранах.

Библиотеки выбираются под потребность, а не ради большого списка зависимостей.
Нужны цель каждой зависимости, совместимые стабильные версии, lockfile и влияние
на bundle. Официальная документация и lockfile существующего проекта важнее
запомненных моделью номеров версий. `latest` не заменяет воспроизводимую фиксацию.

## Документация и проверка

По явной загрузке профиля доступны:

- [Vue с TypeScript](https://vuejs.org/guide/typescript/overview.html).
- [Vite guide](https://vite.dev/guide/).
- [TypeScript handbook](https://www.typescriptlang.org/docs/handbook/intro.html).

Это rolling-документы, не доказательство совместимости любых версий пакетов.
Материалы других UI-библиотек можно импортировать локально; выбранные `.ts`,
`.vue`, `.css` поддерживаются наряду с Markdown. Inference остаётся локальным.

Vite выполняет transpilation, но не заменяет type-checking: для Vue SFC нужен
отдельный vue-tsc. Следует запускать объявленные проектом type-check, tests и
production build, затем проверять сайт в браузере. Lyra пока не исполняет эти
команды сама и не имеет browser-preview/визуального ревью; проверки выполняются
отдельно, с учётом недоверенных install/build scripts.

Рекомендации не гарантируют качество Astra или другой модели. Слабая локальная
GGUF может ошибаться в дизайне, коде и зависимостях. Нужны одинаковые задания,
рабочая сборка, браузерная проверка и оценка результата по согласованным критериям.
Успешный тест движка не измеряет визуальное качество генерации.
