# Дорожная карта

Каждый этап выполняется отдельной задачей. Этот документ не означает разрешение
сразу реализовать все перечисленные функции. Статус основы и проверок — в
[плане M0](plans/0001-repository-foundation.md).

| Этап | Содержание | Критерий завершения |
| --- | --- | --- |
| M0 — основа, текущая задача | GitHub-репозиторий, README, AGENTS.md, выбор языка и границы MVP. | Документы согласованы, ссылки проверены, начальный коммит отправлен в `main`. |
| M1 — нативный CLI | Минимальный Cargo-проект, закреплённый toolchain, аргументы/help, ошибки и отмена, Windows CI. | CLI собирается и запускается в Windows 11 x64; CI без секретов проходит; снят baseline ресурсов. |
| M2 — модель | Адаптер OpenAI Responses API, явная модель, streaming, usage, лимиты и ошибки. | Протокол проверен фикстурами; явно настроенный сквозной запрос работает, секреты не попадают в вывод. |
| M3 — контекст и инструменты | Чтение/поиск, AGENTS.md, патчи, политика доступа, решение и реализация Windows sandbox, разрешённые команды. | Проверены конфликты/CRLF/Unicode, отказ и границы доступа, таймаут и завершение дочерних процессов. |
| M4 — MVP для кодинга | Общий цикл «задача → контекст → патч → тест → отчёт». | На тестовом репозитории агент исправляет дефект, показывает diff и результат теста; чужие изменения сохранены; выполнена нативная Windows-приёмка. |

Приёмка M3 обязательна до включения произвольных команд модели в поставку.
Сборка приложения без неё не означает готовность инструмента исполнения.

## После MVP

Возможные отдельные задачи: TUI, сохранение/возобновление сессий, другие
провайдеры, MCP, интеграция с редакторами, GUI, локальные модели и функции
вне кодинга. Приоритет выбирается по реальному использованию первого MVP.

## Открытые решения

- Конкретная модель, параметры API и бюджет запросов.
- Механизм изоляции Windows и требуемая им версия ОС.
- Версии Rust/зависимостей и численные бюджеты производительности.
- Формат пользовательского конфига и хранения сессий.
- Лицензия, формат поставки и политика обновлений.

Эти решения фиксируются в соответствующей задаче до добавления зависимого кода.
