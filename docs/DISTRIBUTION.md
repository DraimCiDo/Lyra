# Lyra — development alpha

AI-агент для исследования кода, подготовки и проверки предложенных изменений.
Этот пакет использует CPU; CUDA-пакет собирается отдельно.
Это артефакт разработки; стабильный релиз и подтверждение качества 7B/CUDA
не заявлены. Модель GGUF нужно подготовить отдельно.

```powershell
.\lyra.exe --help
.\lyra.exe doctor
.\lyra.exe task --help
.\lyra.exe apply --help
```

Для тестирования в отдельной копии проекта следуйте `docs/ACCEPTANCE.md`.
Демонстрационный проект с намеренной ошибкой находится в `examples/buggy-add`.
Для исполнения его тестов нужен Rust; для запуска готового EXE Rust/Python не нужны.

`task` не меняет проект: он читает выбранные файлы и возвращает JSON-отчёт
с предложениями. `apply --index` применяет выбранное предложение, `apply --all` — весь набор
с проверкой конфликтов и журналом восстановления. `recover` показывает состояние
незавершенной публикации и позволяет завершить ее либо откатить.

Явно выбранная проверка `task --check-config` / `verify` выполняется в Docker
без сети, с read-only исходниками и ресурсными ограничениями. Нужны отдельный
Docker daemon с enforced limits и заранее подготовленный digest-pinned image.
Произвольного host shell у модели нет. Условия: `docs/WORKFLOWS.md`.
Подагенты включаются флагом `--subagents`, работают последовательно с одной
копией весов. Мнение модели-ревьюера не означает успешный исполняемый тест.

Коды выхода: 0 — завершённая команда, 1 — ошибка/незавершённая задача,
2 — неверные аргументы, 124 — таймаут, 130 — отмена.
Проверьте EXE по `SHA256SUMS.txt`. Лицензии зависимостей включены в
`THIRD_PARTY_NOTICES.txt`; они не выбирают лицензию самого проекта.

Исходники и актуальная документация: https://github.com/DraimCiDo/Lyra

## Настольное окно

На Windows откройте `lyra-desktop.exe` двойным щелчком; на Linux —
`./lyra-desktop` в графической сессии. Выберите проект и локальный GGUF,
введите задачу, просмотрите предложения и подтвердите нужную правку.
Инструкции: `docs/DESKTOP.md`. Соседний CLI и установленные
Rust/Python/Node для GUI не нужны. Веса модели в архив не включены.

Windows требует Microsoft Visual C++ v14 x64 Runtime. Если он отсутствует,
установите [официальный пакет Microsoft](https://aka.ms/vc14/vc_redist.x64.exe).
DLL runtime не входят в архив; инструкция и остальные условия — `docs/DESKTOP.md`.

Окно 1160×760; шестерёнка открывает отдельные настройки. Доступны Lucide-иконки,
ползунки, переключатели, четыре темы, RU/EN и отключаемые мягкие анимации.
Параметры и пути сохраняются в локальной папке настроек; задания, код и журнал
автоматически не сохраняются. Отдельное явное сохранение задач для продолжения
включается в настройках помощников: SQLite содержит выбранные исходники и
предложения, хранится локально. Там же выбирается Docker check-config.
Подробности — `docs/DESKTOP.md`, `docs/WORKFLOWS.md`.

Обновление Windows CPU из приложения и восстановление: [UPDATES.md](https://github.com/DraimCiDo/Lyra/blob/main/docs/UPDATES.md).

Главный экран — чат с явным выбором режима Чат/Работа. В режиме Работа
выбранная папка означает работу с существующим проектом;
без папки готовится AI blueprint нового проекта. Уточнения продолжаются сообщениями,
просмотр и создание разделены. Отдельного мастера нет; каркасы остаются в CLI.
Исходники существующих проектов можно дополнять через явные предложения новых файлов.
Документация выбирается в настройках: offline import/search, явная загрузка официальных
источников. Inference локальный по умолчанию; HTTP-провайдер выбирается явно
в настройках с отдельной политикой передачи данных. Инструкции: `docs/PROJECTS.md`, `docs/KNOWLEDGE.md`.
Проверка плана не является компиляцией; внешний shell проекта приложением не запускается.
Веб-профиль Vue/TypeScript и визуальные критерии описаны в `docs/WEB_PROJECTS.md`.
Проверка независимого корпуса и границы оценок качества — `docs/EVALUATION.md`;
developer harness требует checkout исходного репозитория и отдельные toolchains.
