# Настольная Lyra (alpha)

## Запуск на Windows

Скачайте артефакт `lyra-x86_64-pc-windows-msvc` успешного запуска
[GitHub Actions](https://github.com/DraimCiDo/Lyra/actions/workflows/ci.yml)
**ветки с desktop-интерфейсом**. Распакуйте архив и откройте `lyra-desktop.exe`
двойным щелчком. Rust, Python, Node, браузер, сервер и соседний `lyra.exe`
для работы GUI не нужны. Модель в архив не входит: заранее подготовьте
instruction GGUF. Сборка CPU; CUDA здесь не проверена.

Это portable-программа: установщика, подписи издателя и автоматического
обновления пока нет. Не меняйте настройки защиты Windows ради запуска.

1. Выберите папку проекта и файл GGUF в левой панели.
2. При необходимости укажите относительные пути файлов контекста, по одному
   на строке (например, `src/lib.rs`). Пустое поле включает ограниченный индекс.
3. Опишите задачу. По умолчанию: контекст 4096, ответ 512 токенов, 12 вызовов,
   таймаут 600 секунд, CPU threads — доступный параллелизм, максимум 8.
4. Нажмите «Запустить задачу». Во время вычислений окно остаётся доступным;
   «Остановить» завершает процесс модели. Закрытие окна также останавливает task.
   При принудительной остановке частичный отчёт не восстанавливается.
5. Просмотрите итог, выбранный файл и полный исходный/предложенный текст.
   Завершение протокола не доказывает правильность кода. При ошибке откройте
   «Журнал»: он показывает события отчёта и последние 64 KiB stderr движка
   после завершения процесса. Это не потоковый чат.
6. Нажмите «Применить выбранное предложение…», проверьте имя файла и подтвердите.
   Применяется одно предложение; исходник повторно сравнивается. Неполный отчёт,
   повторное применение и изменённый исходник отклоняются. Применение отменять
   посередине записи нельзя; при закрытии окна оно дожидается завершения.
7. Запустите тесты проекта самостоятельно. Мнение AI-ревьюера не заменяет тесты.

«Исследователь и ревьюер» включает последовательные роли одной модели,
без дополнительных копий весов. Это может увеличить время задачи.
«Мой компьютер» собирает локальную диагностику только по кнопке.
Отчёт привязан к исходной папке проекта, даже если после задачи выбрана другая;
корень показывается рядом с предложениями.

Настройки/история автоматически не сохраняются. Временное задание/отчёт
находятся в отдельном системном temp-каталоге и удаляются после worker.
После аварийного завершения ОС temp-каталог может остаться. Экспорт JSON —
явная команда пользователя; он содержит пути и код, не публикуйте его автоматически.
Доступ к файлам ограничивается тем же движком, что и CLI; это не полноценная
песочница ОС. Не работайте с единственным экземпляром важных исходников.

## Проверка на тестовом проекте

Используйте отдельную копию `examples/buggy-add` по [инструкции приёмки](ACCEPTANCE.md).
Сначала выполните Cargo-тест: он должен упасть. В GUI выберите эту копию,
укажите `src/lib.rs`, вставьте текст её `TASK.md` и запустите задачу.
Перед применением проверьте, что тесты не изменены, а `left - right` заменяется
на `left + right`. После применения запустите тест снова: он должен пройти.
Проверьте отмену, ошибку отсутствующей модели, конфликт после внешнего изменения
и разные размеры окна/масштабирование Windows. Тестируйте на копии без watchers.
Качество 7B на пользовательском ПК и CUDA остаются отдельной приёмкой.

## Сборка и автоматические проверки

```powershell
cargo build --release --locked --features desktop --bin lyra-desktop
.\target\release\lyra-desktop.exe
cargo test --workspace --locked --features desktop
cargo clippy --workspace --all-targets --locked --features desktop -- -D warnings
```

GUI использует egui/eframe с wgpu на Windows и OpenGL на Linux. Нужен работающий графический драйвер;
встроенный renderer не связан с CUDA inference. CLI собирается без GUI:
`cargo build --release --locked --bin lyra`.

`lyra-desktop --smoke-test` открывает настоящее окно, выполняет минимум три
прохода UI и закрывается. Успех проверяет создание графического контекста/рендер,
но не взаимодействие с системным файловым диалогом или качество модели.
`--worker` — служебный режим запуска того же CLI в дочернем процессе.
Linux требует системные библиотеки X11/Wayland и `libxkbcommon-x11`;
CI устанавливает их явно и использует Xvfb/Mesa. Windows CI — нативное окно (не Windows 11 пользователя).
