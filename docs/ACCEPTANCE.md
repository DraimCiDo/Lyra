# Проверка alpha: задача → предложение → ревью → применение → тест

Это тестируемая alpha с ограниченными инструментами, а не завершённый автономный
агент. Доступны чтение/поиск, предложения изменений существующих UTF-8 файлов,
опциональные подагенты и отдельный `apply`. Модель не запускает shell, Git,
компилятор или произвольный код. Проверки проекта выполняет тестировщик.
CUDA и качество Qwen 7B на пользовательском ПК требуют отдельной приёмки.

## Подготовка

Нужны CPU-сборка `lyra.exe`, локальный instruction GGUF и Rust для проверки
демонстрационного Rust-проекта. Для работы самого EXE Rust/Python не требуются.
Проверяйте изменения в отдельной копии проекта без работающих редакторов/watchers.
Проверка содержимого перед заменой не является атомарной compare-and-swap с внешними
редакторами; multi-file транзакция и защита от аварийного отключения питания не заявлены.

Из корня клона Lyra, PowerShell:

```powershell
$utf8 = New-Object System.Text.UTF8Encoding($false)
[Console]::OutputEncoding = $utf8
$OutputEncoding = $utf8
$exe = (Resolve-Path -LiteralPath '.\lyra.exe').Path
$model = 'D:\Models\qwen2.5-coder-7b-instruct-q4_k_m.gguf'
$repo = Join-Path (Get-Location) ('.lyra\acceptance-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Force -Path '.lyra' | Out-Null
Copy-Item -LiteralPath '.\examples\buggy-add' -Destination $repo -Recurse
cargo test --offline --manifest-path (Join-Path $repo 'Cargo.toml')
```

Исходный тест **должен упасть**: `add` использует вычитание. Успешный исходный тест
означает, что проверяется другая ревизия/копия. Эталонные тесты не менять.

## Одна роль и предложение

```powershell
$report = Join-Path (Get-Location) '.lyra\report.json'
$json = & $exe task --model $model --repo $repo --task-file (Join-Path $repo 'TASK.md') --file 'src/lib.rs' --context 4096 --max-tokens 512 --timeout-secs 600
$taskExit = $LASTEXITCODE
[System.IO.File]::WriteAllText($report, ($json -join [Environment]::NewLine), $utf8)
Write-Host "task exit=$taskExit"
Get-Content -LiteralPath $report -Raw
```

Ожидается JSON со `status: completed` и одним предложением замены `left - right`
на `left + right`. До `apply` исходный файл должен оставаться неизменным.
Код `1` и статус `invalid_response`, `step_limit` или `model_error` — незавершённая
задача, а не успех. Коды `124`/`130` обозначают таймаут/отмену.
Ограниченная грамматика обеспечивает формат действий, но не качество решения.

`completed` означает, что роли завершили протокол, а не что код корректен.
`model_review_is_verified_test` всегда `false`: мнение ревьюера не подменяет тест.
Отчёт содержит локальный путь и исходный/предложенный код. Не публикуйте его
автоматически; рекомендуемая папка `.lyra/` исключена из Git и контекста агента.

## Явное применение и реальная проверка

После просмотра `proposals[0]`:

```powershell
& $exe apply --repo $repo --report $report --index 0
cargo test --offline --manifest-path (Join-Path $repo 'Cargo.toml')
```

Ожидается успешный тест без изменения его ожиданий. Повторный `apply` того же
отчёта должен отказать с конфликтом. Изменение файла пользователем между `task`
и `apply` тоже должно привести к отказу без перезаписи его содержимого.
За команду применяется только одно выбранное предложение.

## Подагенты

На новой копии fixture повторите `task`, добавив `--subagents`.
Ожидаются роли `researcher`, `coder`, `reviewer`, отдельные истории и общий лимит
`--max-calls` (по умолчанию 12, максимум 24). Исследователь/ревьюер read-only;
рекурсивного делегирования и отдельных копий весов нет. Все запросы идут
последовательно через один экземпляр модели, каждый в новом context.

Сравните время всей задачи, число вызовов, правильность предложения, RAM/VRAM
и исход реального теста при одинаковых параметрах. Подагенты могут улучшить
разбор и проверку, но ускорение не предполагается без замера. Для 8 ГБ VRAM
одна копия весов — исходная конфигурация; параллельный inference пока отсутствует.

## Негативные сценарии

- Запросить `.env`, ключ, игнорируемый файл, `../` или путь за корнем: отказ.
- Подставить symlink/junction на внешний каталог: доступа быть не должно.
- Получить неоднозначную замену: предложение отклоняется.
- Исчерпать шаги/контекст/время: отчёт незавершённый, `apply` отказывает.
- Передать отчёт от другого корня проекта: отказ.
- Попросить модель выполнить команду или расширить права: такого инструмента нет.

Автоматический CI проверяет эти контракты с детерминированным backend и реальным
Rust-тестом до/после. Native smoke отдельно проверяет загрузку одного GGUF,
повторные контексты и грамматику. Это разные доказательства; маленькая smoke-модель
не проверяет качество кодинга и не заменяет эту приёмку на Qwen/Windows 11/CUDA.

## Ресурсные границы текущей alpha

Индекс: до 128 файлов (плюс root AGENTS.md), просмотр до 1024 записей каталогов.
`--file` сужает контекст явно (до 32 путей, с `/` как разделителем).
Один текстовый файл — до 64 KiB, чтение за задачу — 512 KiB, ответ модели за
вызов — 64 KiB. До 8 предложений, не более одного на файл, суммарный текст
предложений — 256 KiB. Ограничение индекса/поиска явно отмечается как неполнота.
Корневой и вложенные gitignore учитываются; скрытые/служебные каталоги,
ключи и GGUF исключаются. Фильтры имён не обнаруживают все секреты, встроенные
в обычный исходник; выбирайте контекст и тестовые данные явно.

`--subagents` делит общий бюджет между двумя помощниками и кодером; роли
сохраняют отдельные истории. Контекст модели не растёт бесконечно: история
ограничена последними четырьмя действиями, native token budget проверяется
на каждом запросе. Переполнение останавливает задачу и не применяет изменения.
