# Lyra

**AI-агент для разработки кода с приоритетом нативной работы в Windows.**

Lyra (Лира) — имя по созвездию Лиры.

Цель — помогать разбираться в репозитории, вносить согласованные изменения,
запускать проверки и объяснять результат. Ориентиры по рабочему процессу —
[Codex](https://github.com/openai/codex) и
[Claude Code](https://code.claude.com/docs/en/overview).

## Состояние проекта

**M1: реализованы Rust CLI и локальная диагностика компьютера.**
Доступны `--help`, `--version`, `doctor` и `doctor --json`, тесты и CI для Linux
и Windows MSVC. Диагностика работает без сети, аккаунта, API-ключа и модели.
Генерация, понимание репозитория, изменение кода и исполнение команд модели
ещё не реализованы. Текущие сборки — артефакты разработки, не стабильный релиз.

## Полностью локальная работа

Lyra проектируется для выполнения AI на ресурсах ПК: локальные веса и локальный
inference, без обязательного SaaS, подписки, внешнего API и отправки кода.
После подготовки весов и runtime работа должна быть возможна без интернета.
Обязательные Ollama, отдельный сервер и облачный fallback не предполагаются.
Подготовка зависимостей/весов может потребовать загрузки заранее; обучение
собственной базовой LLM с нуля в текущий объём не входит.

## Что будет делать первый MVP

| Возможность | Ожидаемый результат |
| --- | --- |
| Работа из терминала | Пользователь задаёт задачу внутри выбранного Git-репозитория. |
| Понимание проекта | Агент читает применимые `AGENTS.md`, ищет код и собирает ограниченный контекст. |
| Изменение кода | Предлагает и применяет патч, показывает итоговый diff и сохраняет чужие изменения. |
| Запуск проверок | Выполняет разрешённые команды, учитывает код выхода, вывод, таймаут и отмену. |
| Работа с моделью | Выполняет локальную модель через отдельный inference-адаптер. |
| Контроль действий | Соблюдает выбранную политику доступа; отделяет предложение модели от разрешения на действие. |
| Отчёт о задаче | Показывает изменённые файлы, результаты проверок, ограничения, токены и локальные ресурсы. |

Первый пользовательский сценарий: открыть тестовый репозиторий, поручить небольшое
исправление, просмотреть изменения и получить результат соответствующего теста.
Для неизвестной или потенциально разрушительной операции агент сначала объясняет
действие и запрашивает разрешение согласно политике сессии.

## Почему Rust

Для ядра и CLI выбран **Rust**: нативная компиляция, отсутствие сборщика мусора,
контроль памяти и доступ к API Windows подходят агенту, который работает с файлами,
процессами и потоковыми сетевыми ответами. Начальная целевая платформа —
**Windows 11 x64**, toolchain **MSVC**, без обязательного WSL.

Язык сам по себе не гарантирует низкий расход ресурсов. Задержку модели, память,
объём контекста и время локальных операций будем измерять отдельно.
Сравнение вариантов и границы модулей — в [архитектуре](docs/ARCHITECTURE.md).

## Начать работу с репозиторием

```powershell
git clone https://github.com/DraimCiDo/Lyra.git
Set-Location -LiteralPath .\Lyra
git status --short
```

Для сборки Windows нужны Rust **1.99.1**, MSVC build tools и Windows SDK;
подробнее — [руководство разработчика](docs/DEVELOPMENT.md).

```powershell
cargo build --release --locked --target x86_64-pc-windows-msvc
.\target\x86_64-pc-windows-msvc\release\lyra.exe --help
.\target\x86_64-pc-windows-msvc\release\lyra.exe doctor
.\target\x86_64-pc-windows-msvc\release\lyra.exe doctor --json
```

Сборки без установки Rust: [GitHub Actions](https://github.com/DraimCiDo/Lyra/actions/workflows/ci.yml)
→ успешный запуск → артефакт `lyra-x86_64-pc-windows-msvc`. Распаковать весь
архив и запустить `lyra.exe doctor` из PowerShell. Для скачивания артефакта GitHub
может потребоваться вход в аккаунт. Сборка и тест на CI не проверяют драйвер
видеокарты и производительность конкретного пользовательского ПК.

`doctor` читает ОС, CPU, RAM, доступные GPU/выделенную VRAM и диски. Недоступные
данные помечаются явно; пустой список GPU не означает отсутствие видеокарты.
Отчёт относится к компьютеру, где запущен CLI. В нём нет hostname, списка
процессов, environment или содержимого проекта; есть точки монтирования дисков.
Ничего не отправляется и автоматически не сохраняется. Коды выхода:
`0` — успешный вывод, `1` — ошибка диагностики/вывода, `2` — неверные аргументы.

## Дальнейшее развитие

После проверенного CLI можно добавить интерактивный TUI, возобновление сессий,
MCP и интеграцию с редактором. Локальная модель — следующий обязательный этап.
Графический интерфейс и функции за пределами кодинга требуют отдельной задачи.

Проект самостоятельный. Использование стороннего кода требует проверки лицензии
и сохранения необходимых уведомлений. Лицензия проекта пока не выбрана;
отсутствие `LICENSE` не предоставляет разрешения на использование кода.
